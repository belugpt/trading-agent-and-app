FBS-REAL connection

  1. On Windows MT5, choose File → Login to Trade Account, enter your FBS MT5 login and password locally, and select FBS-REAL. Your FBS website password may differ. An investor password permits observation only.
  2. Confirm the terminal shows a connected account. Install the indicator and EA; leave ExecuteTrades=false while verifying signals.
  3. On a separate chart attach SME_Monitor. Set SiteOrigin to this dashboard origin, AccountAlias and a unique TerminalId. Configure the owner-provided Site service credential locally.
  4. Allow this HTTPS origin under Tools → Options → Expert Advisors → WebRequest. Never paste broker passwords into this dashboard.
  5. The monitor sends heartbeats; this tab will show reported equity. It does not retrieve earlier account history or adjust changes for deposits and withdrawals.

The dashboard connects through your running desktop MT5 terminal; it does not log directly into FBS. A desktop terminal or Windows VPS must stay running. Phone/web MT5 alone does not run these EAs. Account type, symbol suffixes, tick values, commissions and server history still need terminal verification.

Connection contract

POST endpoint

Accepted event types: heartbeat, setup, deal, error. Each event requires a unique eventId and is deduplicated on receipt. Heartbeat status becomes stale after three minutes.
{ "eventId": "terminal-1:heartbeat:...",
  "kind": "heartbeat",

  "terminal": "terminal-1",
  "equity": 10000, "balance": 10000,

These example amounts are contract documentation, not reported account balances. Only this owner-private Site’s service credential grants machine access.

System boundary
MT5 owns trading and broker credentials. The cloud records events and research and does not contain a remote order endpoint. No live trading is enabled by publishing this app.
Data and privacy
Owner-private Sites access protects the app and machine endpoint. The journal database is shared within that owner-only boundary. Do not make this Site public without adding independent device authentication and per-user storage authorization.
Failure behavior
Missing storage fails requests instead of pretending to save. Disconnected or stale terminals show as such. Duplicate event IDs do not create additional records. A dashboard outage does not remove broker-held stops.
